(1) _resolve_client_args() ->
      {"base_url": f"{PERPLEXITY_API_BASE}/v1", "api_key": <from factory>,
       "max_retries": 0,
       "http_client": httpx.AsyncClient(event_hooks={"response": [self._tap_sse]})}
    A FRESH httpx.AsyncClient per call is required: the parent wraps the SDK
    client in `async with` (openai_responses.py:321), which closes the
    http_client on exit — a reused one would be closed after turn one.

(2) _format_request(...) -> super() then:
      - preset:<name> id  =>  request["preset"] = name; del request["model"]
      - _ensure_object_properties over every {"type":"function"} tool entry
      - per-turn reasoning_effort folded into request["reasoning"]
      - browser-observation hydration preserved (activity context only)
      - DISCOVERED CONSTRAINT (not in the plan text): openai's
        AsyncResponses.create() takes Agent-API-only fields as NEITHER named
        kwargs nor loose **kwargs — it raises
          TypeError: AsyncResponses.create() got an unexpected keyword argument 'preset'
          TypeError: ... unexpected keyword argument 'max_steps'
          TypeError: ... unexpected keyword argument 'skills'
        So the adapter partitions the request against
        inspect.signature(AsyncResponses.create) and moves every non-SDK field
        into `extra_body`, the SDK's documented verbatim-JSON passthrough.
        Verified on the wire (recorded MockTransport request body):
          {"input":[...],"stream":true,"store":true,"background":true,
           "tools":[...],"preset":"high","max_steps":100,
           "skills":[{"type":"builtin","name":"office"}]}
        i.e. `preset`/`max_steps`/`skills` land at the JSON top level, exactly
        as the Agent API expects, and `model` is absent for preset ids.
      - store: the parent writes `"store": self.stateful` AFTER merging
        **params (openai_responses.py:558-564), so __init__ sets
        stateful=bool(params.get("store")). Asserted by
        test_store_survives_the_parents_stateful_override (store=True on wire).

(3) Native-event tap at the HTTP layer. `_tap_sse(response)`: no-ops unless
    content-type starts with text/event-stream; otherwise replaces
    response.aiter_bytes with a wrapper that forwards every byte UNCHANGED to
    the SDK and, line by line, json-parses each `data:` line. A payload is
    queued when its `type` starts with `response.reasoning.`, equals
    `response.skill.loaded`, or is `response.output_item.done` whose
    `item.type` is in config.NATIVE_OUTPUT_ITEM_TYPES.
    `stream(...)`: drains the queue before each parent chunk and once more
    after the parent finishes, yielding `{"perplexity": <parsed dict>}`.
    Byte-for-byte identity asserted by
    test_forwarded_bytes_are_identical_to_the_server_body.
    route.ts NOT touched.
