# Native compare streaming — research and regression evidence

## Decision

Retire the unused Next compare SSE route, not replace its custom event envelope
with an incompatible UI-message envelope. The compare page already renders one
independent `AgentChat` per pane. Each uses `useChat` and `DefaultChatTransport`
against the existing orchestrator bridge. No frontend runtime consumer of
`/api/compare` was found.

The repository framework reset plan explicitly prescribes this retirement and a
red-first compatibility test (V10 / task 17). This change implements the frontend
portion only. The Python compare endpoint, workflow and worker registration are
left intact; their later removal is **not** claimed complete here. External users
of the undocumented legacy Next endpoint would receive 404 after deployment;
the supported compare page continues using the regular session endpoint.

`DefaultChatTransport` validates the UI-message chunk schema. The existing bridge
uses `createUIMessageStream` and `createUIMessageStreamResponse`; the SDK owns SSE
framing, encoding, termination and response headers. The legacy route's
`{model,type:delta,text}` frames are not native UI-message chunks. Adapting them
would maintain an unnecessary second pipeline, not improve the current UI.
