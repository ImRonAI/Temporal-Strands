# Durable Strands Temporal Orchestrator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the deleted Python service as a replay-safe Temporal-hosted Strands agent while preserving the current Next.js HTTP, SSE, approval, comparison, and graph contracts.

**Architecture:** One `ChatWorkflow` owns each session and accepts serialized turn Updates, approval and end Signals, and message Queries. Worker-side factories own Perplexity clients, MCP transports, PopHIVE processes, LanceDB, and all other I/O; Workflow code holds only serializable state and Temporal handles. A custom `PerplexityModel` maps `/v1/agent` streams to native Strands events, while focused Activities implement response lifecycle, files, memory, graph work, and persistence hooks.

**Tech Stack:** Python 3.13, Temporal Python SDK with `temporalio[strands-agents]`, Strands Agents, Perplexity Python SDK, FastAPI, MCP, LanceDB, pytest/pytest-asyncio, Next.js 16, Vitest, pnpm.
